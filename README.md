# CPU 格闘ゲーム（開発版）

Windows 向けの小規模な 2D CPU 対戦ゲームです。C# / [.NET 10 LTS](https://dotnet.microsoft.com/en-us/platform/support/policy) と [MonoGame DesktopGL 3.8.6](https://www.nuget.org/packages/MonoGame.Framework.DesktopGL/3.8.6) を使用します。MonoGame の公式 NuGet パッケージは .NET 8 用アセンブリを提供し、Windows 10 (22H2 以降) を含むデスクトップ環境を対象に SDL2/OpenGL の描画・入力を提供します。.NET 8 は2026年11月にサポート終了予定のため、2028年までサポートされる .NET 10 をアプリの対象にしています。ライセンスと配布条件は [`THIRD-PARTY-NOTICES.txt`](THIRD-PARTY-NOTICES.txt) と各公式パッケージ情報を参照してください。

## 実行・確認

開発環境に .NET SDK 10.0.401 (または同じ feature band の最新パッチ) を用意し、リポジトリのルートで実行します。

```powershell
dotnet restore
dotnet run -- --self-test
dotnet run
```

`--self-test` は描画ウィンドウを開かず、4ボタン入力、同時押しの順序・押しずれ、状態遷移、連係、ID登録、硬直、当たり判定、移動と操作説明を検査します。検査用設定は一時ディレクトリに保存し、実際のユーザー設定は変更しません。破損設定・保存失敗のテストでは、意図したエラー通知が標準エラーに出ます。

## 操作

- `Enter`: 説明画面から対戦開始・再開 / 結果画面から再戦準備
- `Space` またはチェック欄のクリック: 説明画面の「次回からこの説明を表示しない」を切替
- `F1`: 対戦中の操作説明を開く・閉じる（対戦全体を一時停止）
- 矢印キー / WASD: 移動、上でジャンプ、下でしゃがみ。既存の後ろ入力による地上ガードも維持
- `J`: 弱、`U`: 中、`K`: 強、`L`: ガード。既存の J / K を維持し、空いていた U / L を追加
- `L + 下`: 特殊ガード・納刀
- `J+U` / `J+K` / `U+K`: 同時押し。`U+K` は両状態とも未定で、何も発動せず `UndefinedCommand` を通知
- `F3`: 両者の状態、技名（日本語）、数値ID、文字列キー、連係元ID、派生段階、フレーム、要求結果、強化・回避成功・切っ先接触を表示
- `Escape`: 終了

旧2ボタン用の波動コマンド必殺技と F2 の直接発動は、今回の固定技体系に置き換えました。ゲージ表示と被弾・攻撃による蓄積は残していますが、新技ではゲージを消費しません（仮設定）。ウィンドウが非アクティブになると更新を止め、復帰時は操作キーがいったん離されるまで入力を無視します。

### 入力・状態・連係

同時押しの判定が終わるまで単押しを保留します。既定の押しずれは3フレーム（60 FPSで約50 ms）、先行入力は押した時点から8フレームで、`CombatTuning` から変更できます。猶予内の2ボタンは一つの複合入力として消費し、構成する単押しは発動しません。3ボタン同時押しも未定扱いで、単押しには分解しません。単押しにも3フレームの遅延がある点は試作用のトレードオフです。

`J+U` は同時押し、`J → U` は手刀または斬の**発動後**にUを押す操作です。手刀なら回転剣舞、斬なら肉骨断罪へ派生します。手刀はヒット・空振りを問わず全行動にキャンセル可能で、自身・特殊ガード・移動・ジャンプ・通常ガードも含みます。各行動自体の地上条件・状態条件は確認します。移動を押したまま手刀を始めても、その場で自動キャンセルはせず、発動後の新しい移動入力でキャンセルします。

鞘当ては `U → U → U` で「鞘の突き → 抜刀して回転斬り → 突き・納刀」の3段階です。回転剣舞とは独立しており、途中で抜刀しても `SayaAte` のままです。回転剣舞は初回を1回転とし、中を5回追加入力して最大6回転です。斬は**初段＋追加入力3回＝最大4段**と解釈しています。各連係は次の1段を予約でき、1入力は1度だけ消費します。入力した段の攻撃判定終了後に次段へ進みます。IDと段階番号は別で、実行状態は各 `Fighter.Execution` にのみ保存します。

納刀／抜刀は行動が終了・中断しても維持されます。技の終了・被弾で連係は破棄しますが、刀の状態は戻しません。

### 仮設定・未確定部分（要確認）

既存実装には刀の状態も中・ガードボタンもなかったため、次を試作用に採用しています。確定値ではありません。

- 初期状態は納刀。神速抜刀・回転剣舞は発動要求が受理された瞬間に抜刀。鞘当ては第2段開始時に抜刀、第3段開始時に納刀。閃光剣は未実装なので状態も変更しません。
- 特殊ガードは地上の待機・移動・しゃがみ、および手刀キャンセルから受け付けます。硬直・他技の途中では発動不可（通常の短い先行入力は適用）。受理時に即納刀し、防御成功は不要。18フレームの行動硬直は別に残します。仮の防御性能は、その間は向きに関係なく既存の通常ガード相当（被弾時にガード硬直へ移行）です。新技の削りは仮に0。
- 全技のダメージ・発生・持続・硬直・範囲・無敵・アーマー時間・キャンセル受付・移動速度・ゲージは試作用です。技固有の値は `Moves/*Move.cs`、入力・効果時間・倍率は `Combat/CombatMove.cs` の `CombatTuning` にあります。手刀の自由キャンセルにヒット条件・段数制限は加えていません。
- 深呼吸の3秒は180シミュレーションフレーム。仮の「速度」は地上歩行と技による前進だけを1.25倍にし、ジャンプ・発生・硬直・アニメーションは変えません。「抜刀へ移行する技」は神速抜刀・回転剣舞、および鞘当て第2段。対象の技／段の開始時に強化が残っていれば、その技／段のダメージ倍率を1.25倍として記録します。ほかの段や斬には適用しません。倍率・対象・開始時記録方式は要確認。
- 突破は入力開始時の画面基準の方向（上・下・斜めを含む）を正規化して固定し、無方向なら発動時の向きへ突きます。空中技ではなく地上から上下にも突ける仮実装で、斜め判定は線分を囲む矩形による近似です。方向方式・無入力時の扱いは要確認。
- 滑刃走破は前方突進と、切っ先12ピクセルの判定領域を実装。相手の攻撃判定との接触をF3に表示しますが、**カウンター成立条件・報酬・相殺・無敵は未実装**です。接触をカウンター成功と扱いません。肉骨断罪のアーマーは行動中全体に適用し、ダメージを受けても行動と位置を維持する仮設定です。
- 完全回避は無敵14フレーム、開始後6フレーム以内に相手の有効な攻撃判定と実際に重なった場合のみ成功とする仮設定です。無敵でダメージを無効化する判定と成功判定は別です。成功後の攻撃キャンセルは24フレーム。成功時は全実装済み攻撃へのID指定派生を許可する仮解釈（通常の状態・派生専用条件の代わりに回避成功を確認）で、ボタン入力は現在の刀状態のコマンド表を使います。状態をまたぐ攻撃への直接派生を許可するかは要確認。非攻撃の深呼吸・特殊ガード・完全回避へは成功専用キャンセルしません。
- 閃光剣・滞空突破は登録枠のみ。`Unimplemented` を返し、硬直・ダメージ・状態移行を発生させません。中＋強は登録枠も新技も作りません。

### 完全回避の操作補助案

**未確定・初期値は無効**です。まずは成功後24フレームの受付で極端に短い入力を不要にしています。試作候補は `CombatTuning.EvadeAssistEnabled = true` で有効にできます。成功時に6フレームの短い全体停止を入れ、その間も双方の攻撃入力を受け付けます。成功前8フレーム以内の攻撃入力を記憶し、成功した場合だけ攻撃へ移行します。失敗時は攻撃キャンセルを許可しません。無効時は成功前に押した入力による成功専用キャンセルを行いません。停止演出・先行入力・受付時間は操作感の実機評価後に採用可否と数値を決める提案であり、確定仕様ではありません。

### 構成と技の追加

`Moves/` は1技1ファイルです。鞘当ての3段階は `SayaAteMove.cs`、回転剣舞は `KaitenKenbuMove.cs` に分かれています。共有の入力・同時押し・先行入力は `CommandInput`、入力とIDの対応は `CommandDefinitions`、登録・検索は `MoveRegistry`、発動条件と開始・終了は `MoveController`、衝突・ダメージ・効果時間の進行は共通の対戦処理に置いています。技オブジェクトは共有ですが、段階・回転数・経過フレーム・予約入力はキャラクターごとに保持します。

数値・キーの対応は `MoveRegistry.Default` の一か所だけです。起動時に重複ID・重複キー・存在しない派生先を検出し、コマンド定義の参照IDも検証します。検索例は `MoveRegistry.Default.TryGet(MoveIds.Shuto, out var move)` と `TryGet("shuto", out var move)`。発動は `MoveController.Request(fighter, MoveIds.Shuto)` または `Request(fighter, "shuto")`。後者も同じ発動条件を通ります。失敗は `MoveRequestResult` と画面の要求結果で明示します。

新技を追加する手順:

1. `Moves/ExampleMove.cs` を作成し、`CombatMove` を継承。性能、固有挙動、状態移行、追加入力、キャンセル、`BranchTargets` をそのファイルへ記述。可変の実行情報は `MoveExecution`／`Fighter` に保持し、共有技オブジェクトに保存しない。
2. `MoveIds` に未使用の明示的な数値定数を追加し、`MoveRegistry.Default` にその定数・一意キー・正式名・英字表示名・技オブジェクトを登録。既存IDを変更しない。削除したIDも予約済みとして残し、再利用しない。
3. `CommandDefinitions.Bindings` または `Branches` に入力とIDを登録。派生の場合は元技の `BranchTargets` / `CanBranchTo` も追加。入力側で技クラスを生成しない。
4. 操作説明とこの表を更新し、`BattleVerification` に状態・派生・不正なID発動・対戦者間分離の検査を追加して `dotnet run -- --self-test` を実行。

### 操作説明と保存設定

初期状態では起動直後に日本語の操作説明を表示し、`Enter` または開始ボタンで対戦が始まります。再戦も対戦開始前に説明を表示します。説明は「基本操作」「納刀中の技」「抜刀中の技」の3ページで、左右矢印キーまたは画面のページボタンで切り替えます。説明画面は不透明で、文字はNoto Sans CJK JP由来の日本語グリフを使います。チェック欄「次回から表示しない」は初期値 OFF です。チェックの切替だけでは対戦は始まりません。ON で保存した場合は、次の起動時も説明を省略して対戦が始まります。

説明画面のキー名は入力処理と同じ `GameData.Controls` を参照します。両状態の技名、実際に押すキー、追加入力、特殊ガード、未実装枠を表示します。フォントの再配布条件は `Assets/NotoSansCJK-OFL.txt` に記載しています。

設定は変更時に `%LOCALAPPDATA%\Chozetumokosatugekiranzan\settings.json`（.NET の `LocalApplicationData`）へ保存し、ゲーム終了後も保持します。インストール先には書き込みません。設定がない場合や JSON が壊れている場合は説明表示が有効になり、ゲームは起動できます。読込・保存エラーは画面下部と標準エラー出力へ通知し、保存失敗時の変更はその起動中だけ有効です。

自動表示を省略していても、対戦中は `F1` でいつでも説明を開けます。表示中は CPU、制限時間、移動、攻撃、硬直、アニメーションを含む対戦更新を停止します。同じ画面でチェックを OFF に戻せば、次の対戦・再戦から自動表示が復活します。`Enter` または `F1` で再開します。開閉時に入力履歴を消去し、操作キーとマウス左ボタンが離されるまで更新を止めることで、攻撃・ジャンプの入力が対戦に流れ込むのを防ぎます。

```powershell
dotnet publish -c Release -r win-x64 --self-contained false -o publish/win-x64
```

## 手動確認

この実行環境で確認するのは Linux 上のビルドとヘッドレス検証のみです。Windows の描画・キーボード・実際の操作感は未確認です。Windows PC のリポジトリルートで上記 `dotnet restore`、`dotnet run -- --self-test`、`dotnet run` を順に実行してください。

F3 を有効にし、初期納刀、J+Uで完全回避（手刀なし）、J発動後Uで回転剣舞、U→U→Uで別連係の回転斬り・突き・納刀、Kで抜刀、抜刀J→Uで肉骨断罪、L+下で被弾なしの即納刀を確認してください。回転剣舞はUの追加入力で最大6回転、斬はJの追加入力で最大4段となり、CPUの段階表示と混ざらないことも確認してください。手刀の空振りからJ再入力・L+下・移動・ジャンプができること、U+Kで単押し技が出ないこと、抜刀K／J+Uが `Unimplemented` となることを確認してください。移動・着地・ガード・CPUの攻撃・KO・再戦、および強化の速度・効果時間も実機確認対象です。回避の成功窓・成功後受付・任意の補助機能の操作感と、同時押し時のキーボード同時認識は、ヘッドレス検証だけで確認済みとは扱いません。

操作説明は、設定ファイルを退避した初回表示、OFF のまま再戦した場合の表示、ON にした場合の省略、終了・再起動後の省略維持を確認してください。対戦中に F1 で再表示して CPU・タイマーが停止すること、マウスと Space の両方で切り替えられること、OFF に戻すと再戦・再起動後に再び表示されることも確認してください。開閉と同時に W / J / K を押したり押し続けたりしても、再開直後にジャンプ・攻撃しないことを確認してください。
